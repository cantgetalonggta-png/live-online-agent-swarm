## Chapter 1 — Latent Vector Space (LVS)

### Foundational Theory
A latent vector space is a high-dimensional numeric field where meaning is geometry. Claims, documents, agents, and hypotheses occupy positions. Distance is disagreement; direction is a modifier. Superposition (many concepts sharing one direction) is the failure mode when the object grammar is too coarse.

### Phase 1 — Preparation (define the space)

#### Step: Declare objects that may occupy the space
**Why:** Wrong unit of analysis makes every similarity a lie.
**Execution:**
1. Enumerate object types: Document, Chunk, Entity, Claim, Hypothesis, Agent, Modifier, Artifact.
2. Assign stable IDs: C01…, H1…, sk_*, agent ids.
3. Forbid pooling a whole 557-page report into one vector. Grain = one claim.
4. Record provenance: URL/PDF page, timestamp, hash.
**Tools:** Public-record ceiling, SHA-256, claim schema, geometry-over-rhetoric mindset.
**Pitfalls:** Embedding headlines → rewrite as testable tagged propositions; one vector per agent report → one vector per finding.
**KPI:** Every object type has an example ID; no unlabeled blobs.

#### Step: Choose decision-relevant axes
**Why:** Mixing process failure with origin inference turns 7.1M deaths into false proof of manufacture.
**Axes:** (A) epistemic tag SOLID/CONTESTED/OVERSTATED/IRREGULARITY (B) hypothesis support H1/H2/H3 (C) source quality (D) conflict-of-interest.
**KPI:** New claim plotable on all four axes in <2 minutes.

### Phase 2 — Execution (place objects)
#### Step: Ingest and chunk at claim grain
**Why:** Late-interaction / multi-vector storage preserves rare identifiers (R01AI110964, DEFUSE, March 25).
**Execution:** Hash source → section extract → claim split → Claim—SUPPORTED_BY→Source graph edges.
**KPI:** Every claim has page/doc pointer; extraction coverage % known.

## Chapter 2 — System-Level Modifier Validation Pipeline (SLMVP)

### Foundational Theory
A modifier steers the latent space. System-level means enforced on the whole swarm. Validation tests whether the modifier changed geometry honestly or just flipped partisan sign. Unvalidated anti-mainstream becomes new dogma.

### Registered Modifiers (permanent)
| ID | Name | Pass/Fail Test |
|----|------|----------------|

| M2 | HITL=YES | Bulk ingest / GitHub / Drive need operator auth |

| M4 | Tag discipline | SOLID only with primary documents |
| M5 | Process ≠ origin | Debarment/FOIA/6-ft do not close H1 |

### Phase 1 — Register modifiers
Atomize each rule with a test. Named modifiers = add/remove vectors in latent arithmetic.

### Phase 2 — Validate against both tribes
Equal effort to kill H1 and H2. Mortality is outcome axis; origin is mechanism axis. CIA low-confidence ≠ high probability.
**KPI:** Every C01–C11 card has FOR, AGAINST, tag, modifier IDs.

## Chapter 3 — Atomized Artifact Output (AAO)

### Foundational Theory
Output is atoms: SkillAtoms, ClaimAtoms, Agent reports, ACH posteriors, HTML dashboards, Drive/GitHub hashes. Representability + sparsity + separability.

### Phase 1 — Emit atoms
